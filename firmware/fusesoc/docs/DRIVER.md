# PeakRDL Driver Generation

This document describes how to generate Python drivers for QICK IP cores
using [PeakRDL](https://peakrdl.readthedocs.io) and SystemRDL.

## Overview

PeakRDL enables a **single source of truth** approach where you define your
IP's register map once in a `.rdl` file and automatically generate:

- **Python**: register-access package (`peakrdl python`) with an in-memory simulator
- **QICK Driver**: Python class (manual or generated) that uses the register package
- **HTML Documentation**: register map docs (`peakrdl html`)
- **SystemVerilog** (OPTIONAL): an AXI4-Lite register block (`peakrdl regblock`)

> IMPORTANT — two RTL strategies
>
> There are two ways an IP can implement its AXI register decode, and this
> determines whether you generate SystemVerilog from the RDL:
>
> 1. **Generated regblock (simple register-only IPs)**
>    Example: `axis_constant_iq`. The RTL register block IS generated by
>    `peakrdl regblock` (via the `--hdl` flag) and instantiated in the IP.
>    The RDL is the source of truth for BOTH the RTL and the driver.
>
> 2. **Custom AXI slave (IPs with memory windows / handshakes)**
>    Example: `axis_tprocv1`. The RTL register decode is a hand-written module
>    (`axi_slv_tprocv1`) because the IP needs features `peakrdl regblock` cannot
>    express: a data-memory access window mapped to the upper AXI address
>    space, an exec/exec_ack handshake to a memory arbiter, and SLVERR
>    responses while memory is busy. In this case you must NOT generate RTL
>    from the RDL — the RDL is used ONLY for the Python driver layer and
>    documentation. Pass only `--python` (and optionally `--html`), never
>    `--hdl`, or the generated regblock will conflict with `axi_slv_tprocv1`.
>
> Pick the strategy per IP. The `make new-ip` template defaults to `--hdl
> --python` (strategy 1); edit the IP's `rdl/Makefile` to remove `--hdl` if
> the IP uses a custom AXI slave (strategy 2).

```
cores/ip/<ip_name>/
├── rdl/
│   ├── <ip_name>_regmap.rdl          ← SOURCE OF TRUTH (you edit this)
│   ├── <ip_name>_regmap.core
│   ├── Makefile
│   ├── <ip_name>_regmap_pkg/         ← Generated Python package (gitignored)
│   └── docs/                         ← Generated HTML docs (gitignored)
├── driver/
│   ├── <ip_name>.py                  ← QICK driver (symlinked to qick_lib/)
│   └── tests/                        ← Python register-layer tests (pytest)
│       ├── conftest.py
│       └── test_<ip_name>_regs.py
├── hdl/
│   └── <ip_name>.sv
└── test/                             ← SVUnit RTL testbenches
    ├── <ip_name>_tc00.sv
    └── <ip_name>_tests.sv
```

## How It Works on the RFSoC Board

When you run `make driver`:

1. The generated PeakRDL package is produced in `cores/ip/<ip_name>/rdl/<ip_name>_regmap_pkg/`.
2. The driver is **symlinked** to `qick_lib/qick/drivers/<ip_name>.py`.
3. (Optional) HTML documentation is generated with `make rdl-docs`.

If your driver imports the generated package, it can search multiple locations
so it works both in development and on the board:

```python
_RDL_PKG_PATHS = [
    Path(__file__).parent.parent / "rdl",        # dev: next to driver
    Path(__file__).parent.parent / "rdl_pkgs",   # prod: installed with QICK
]
```

> NOTE: A manual driver (like the tProcV1 driver) may NOT import the generated
> package at all — it can access registers via hardcoded offsets
> (`self.mmio.array[idx]`). In that case the generated package is optional and
> serves as documentation / a base for register-layer tests. Decide per IP
> whether the driver depends on the generated package.

## Quick Start

### For an existing IP

```bash
cd firmware/fusesoc
source venv/bin/activate

# Generate the driver layer (RDL -> Python package + QICK symlink)
make driver IP=axis_constant_iq

# Generate HTML documentation
make rdl-docs IP=axis_constant_iq

# Simulate the RTL (SVUnit)
make sim IP=axis_constant_iq
```

### Creating a new IP

```bash
cd firmware/fusesoc

# Create IP structure from template
make new-ip IP=my_new_ip

# Edit the RDL to define your registers
vim cores/ip/my_new_ip/rdl/my_new_ip_regmap.rdl

# If this IP uses a CUSTOM AXI slave (not a generated regblock), edit
# cores/ip/my_new_ip/rdl/Makefile and remove --hdl from the gen target.

# Generate the driver layer
make driver IP=my_new_ip

# Generate docs
make rdl-docs IP=my_new_ip
```

## The rdl/Makefile

Each IP's `rdl/Makefile` derives the IP name from the directory and invokes the
generator. The correct form is:

```makefile
IP_NAME    = $(shell basename $(shell dirname $(CURDIR)))
RDL_FILE   = $(IP_NAME)_regmap.rdl
GEN_SCRIPT = ../../../../generators/systemrdl/rdl_tools.py

gen:
	python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --python   # add --hdl only for regblock IPs

docs:
	python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --html

clean:
	rm -rf $(IP_NAME)_regmap_pkg $(IP_NAME)_regmap*.sv $(IP_NAME)_regmap*.svh

.PHONY: gen docs clean
```

> CRITICAL — common Makefile bugs (learned the hard way)
>
> 1. **IP_NAME path depth**: `$(CURDIR)` inside `rdl/` is
>    `.../cores/ip/<IP_NAME>/rdl`. To get `<IP_NAME>` you need exactly ONE
>    `dirname` (rdl -> <IP_NAME>) then `basename`. Using TWO `dirname` calls
>    climbs to `cores/ip` and `basename` returns the literal `ip`, producing
>    a bogus `ip_regmap.rdl`. Use a single `dirname`.
>
> 2. **Recipe lines need TABs**, not spaces. If your editor converts tabs to
>    spaces, Make fails with "missing separator".
>
> 3. **Add a `docs` target** so `make rdl-docs` works (uses `--html`).
>
> 4. **Strategy 2 IPs must drop `--hdl`** from `gen` so the generated regblock
>    does not conflict with the hand-written AXI slave (`axi_slv_tprocv1`).

### Fixing the new-ip template (create_ip.sh)

`scripts/create_ip.sh` writes the per-IP `rdl/Makefile` via a heredoc. Two bugs
were found and fixed there:

1. The heredoc must use a **quoted delimiter** (`<< 'EOF'`) so bash does NOT
   expand `$` — then write `$(...)` literally WITHOUT backslashes. Using an
   unquoted `<< EOF` with a duplicated `RDL_FILE = $(IP_NAME)_regmap.rdl` line
   made bash run command substitution `$(IP_NAME)` (an unknown command),
   producing an empty `RDL_FILE = _regmap.rdl`.

2. TABs in heredocs are fragile. Write a placeholder `@@TAB@@` for recipe-line
   indentation and convert it to a real tab after the heredoc:

```bash
cat > $IP_DIR/rdl/Makefile << 'EOF'
IP_NAME    = $(shell basename $(shell dirname $(CURDIR)))
RDL_FILE   = $(IP_NAME)_regmap.rdl
GEN_SCRIPT = ../../../../generators/systemrdl/rdl_tools.py

gen:
@@TAB@@python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --hdl --python

docs:
@@TAB@@python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --html

clean:
@@TAB@@rm -rf $(IP_NAME)_regmap_pkg $(IP_NAME)_regmap*.sv $(IP_NAME)_regmap*.svh

.PHONY: gen docs clean
EOF
sed -i 's/@@TAB@@/\t/g' $IP_DIR/rdl/Makefile
```

Verify a newly created IP:

```bash
./scripts/create_ip.sh test_dummy
cat -A cores/ip/test_dummy/rdl/Makefile   # expect ^I (tab), no \$, no @@TAB@@
cd cores/ip/test_dummy/rdl && make -n gen # expect: ... test_dummy_regmap.rdl ...
cd - && rm -rf cores/ip/test_dummy
```

## SystemRDL File Format

The `.rdl` file is the single source of truth for your IP's registers.

**Example: `axis_constant_iq_regmap.rdl`** (regblock IP, strategy 1)

```systemrdl
addrmap axis_constant_iq {
    name = "AXIS Constant IQ Registers";
    desc = "Registers for the axis_constant_iq IP core.";
    default regwidth = 32;
    default accesswidth = 32;
    default addressing = compact;

    reg {
        name = "REAL_REG";
        desc = "16-bit I (real) component of the constant output.";
        field { name = "I"; desc = "In-phase component"; sw = rw; hw = r; } I[15:0] = 0;
    } REAL_REG @0x00;

    reg {
        name = "IMAG_REG";
        desc = "16-bit Q (imaginary) component of the constant output.";
        field { name = "Q"; desc = "Quadrature component"; sw = rw; hw = r; } Q[15:0] = 0;
    } IMAG_REG @0x04;

    reg {
        name = "WE_REG";
        desc = "Write-enable strobe. Writing 1 triggers an IQ update.";
        field { name = "WE"; desc = "Write Enable."; sw = rw; hw = r; swmod; } WE[0:0] = 0;
    } WE_REG @0x08;
};
```

**Example: `axis_tprocv1_regmap.rdl`** (custom AXI slave IP, strategy 2)

For an IP whose RTL decode is a hand-written `axi_slv_tprocv1`, the RDL describes
ONLY the control registers (the register layer the driver/docs need). The
single-access data-memory window (upper AXI address space) is handled by
`axi_slv_tprocv1` in RTL and by the driver in software; it is intentionally NOT
modeled here.

```systemrdl
addrmap axis_tprocv1 {
    name = "axis_tprocv1 Registers";
    desc = "Control registers for the QICK tProcessor V1. The single
            data-memory access window (upper AXI address space) is handled by
            axi_slv_tprocv1 and the manual driver; it is not part of this map.";
    default regwidth = 32;
    default accesswidth = 32;

    reg { field { sw = rw; hw = r; } START_SRC[0:0] = 0; } START_SRC_REG @ 0x00;
    reg { field { sw = rw; hw = r; } START[0:0]     = 0; } START_REG     @ 0x04;
    reg { field { sw = rw; hw = r; } MEM_MODE[0:0]  = 0; } MEM_MODE_REG  @ 0x08;
    reg { field { sw = rw; hw = r; } MEM_START[0:0] = 0; } MEM_START_REG @ 0x0C;
    reg { field { sw = rw; hw = r; } MEM_ADDR[31:0] = 0; } MEM_ADDR_REG  @ 0x10;
    reg { field { sw = rw; hw = r; } MEM_LEN[31:0]  = 0; } MEM_LEN_REG   @ 0x14;
};
```

> NOTE: Do NOT model the data-memory window as `external mem` in the RDL for a
> driver-only flow. `peakrdl regblock` would generate external-memory interface
> ports (strategy 1), and `peakrdl python` would generate memory accessors you
> do not use. Keep the RDL to just the control registers when the driver
> handles memory access manually.

### Common RDL Patterns

Self-clearing strobe:

```systemrdl
field { swmod; } WE[0:0] = 0;
```

Read-only status with write-clear:

```systemrdl
field { sw = rw; hw = w; swmod; onwrite = woclr; } IRQ_FLAG[7:0];
```

Counter with read-clear:

```systemrdl
field { sw = r; hw = r; counter; onread = rclr; } COUNTER[31:0];
```

Arrays of registers:

```systemrdl
reg { field { sw = rw; hw = r; } DATA[31:0]; } CHANNEL[4] @0x10;  // CHANNEL[0..3]
```

## Generated Python Package

After `make driver`, PeakRDL-python (3.1.2) generates a package whose layout is:

```
<ip_name>_regmap_pkg/
├── reg_model/
│   ├── __init__.py            ← exports `RegModel` (clean alias)
│   └── <ip_name>.py           ← register model class (hash-suffixed name + alias)
├── sim/
│   ├── __init__.py            ← exports `Simulator`
│   └── <ip_name>.py           ← <ip_name>_simulator_cls (in-memory model)
├── lib/                       ← runtime classes (NormalCallbackSet, etc.)
├── sim_lib/                   ← simulator helper classes
└── tests/                     ← PeakRDL-generated unit tests (reference!)
    ├── _<ip_name>_sim_test_base.py   ← shows EXACT instantiation pattern
    └── test_sim_<ip_name>.py
```

> Confirming the generated API
>
> The class name in `reg_model/<ip_name>.py` may be hash-suffixed, e.g.
> `axis_tprocv1_neg_0x529130c5eb3f85b1_cls`. PeakRDL provides a clean alias at
> the bottom of the file (`axis_tprocv1_cls = ..._cls`) and, more importantly,
> `reg_model/__init__.py` re-exports it as `RegModel`. Always import the clean
> aliases:
>
>   from <ip_name>_regmap_pkg.reg_model import RegModel
>   from <ip_name>_regmap_pkg.sim import Simulator
>   from <ip_name>_regmap_pkg.lib import NormalCallbackSet
>
> The authoritative usage pattern is in
> `tests/_<ip_name>_sim_test_base.py`. Read it before writing your own tests.

### NormalCallbackSet needs FOUR callbacks

In PeakRDL-python 3.1.2 the simulator wiring requires read/write AND their block
variants:

```python
from <ip_name>_regmap_pkg.reg_model import RegModel
from <ip_name>_regmap_pkg.sim import Simulator
from <ip_name>_regmap_pkg.lib import NormalCallbackSet

sim = Simulator(address=0)
model = RegModel(
    callbacks=NormalCallbackSet(
        read_callback=sim.read,
        write_callback=sim.write,
        read_block_callback=sim.read_block,
        write_block_callback=sim.write_block,
    )
)
```

> If you only pass `read_callback`/`write_callback` (older 2-arg pattern), it may
> fail. The 4-callback form matches the generated `_*_sim_test_base.py`.

### Sync vs Async

PeakRDL-python generates BOTH sync and async APIs (note the many `async_*`
modules under `lib/`). The default model (`RegModel`) is the **synchronous**
one, with `.read()` / `.write()`. If you ever import the async classes you must
use `async def` + `await` + `pytest-asyncio`.

### Generated API

```python
model.REAL_REG.I.write(100)       # write field
model.REAL_REG.I.read()           # read field -> 100
model.REAL_REG.write(200)         # write full register
model.REAL_REG.read()             # read full register -> 200

model.REAL_REG.address            # -> 0x00
model.REAL_REG.I.high             # -> 15
model.REAL_REG.I.low              # -> 0
```

## Testing Without Hardware (pytest)

You can test the register layer / driver sequences without an RFSoC board using
the generated simulator. Recommended layout:

```
cores/ip/<ip_name>/driver/tests/
├── conftest.py                 ← puts the generated package on sys.path
└── test_<ip_name>_regs.py      ← your pytest tests
```

**conftest.py**

```python
import sys
from pathlib import Path

# driver/tests/ -> ../../rdl/ contains <ip_name>_regmap_pkg/
_RDL_DIR = Path(__file__).resolve().parents[2] / "rdl"
if str(_RDL_DIR) not in sys.path:
    sys.path.insert(0, str(_RDL_DIR))
```

**test_<ip_name>_regs.py** (example for axis_tprocv1)

```python
import pytest
from axis_tprocv1_regmap_pkg.reg_model import RegModel
from axis_tprocv1_regmap_pkg.sim import Simulator
from axis_tprocv1_regmap_pkg.lib import NormalCallbackSet


def make_sim_regs():
    sim = Simulator(address=0)
    return RegModel(
        callbacks=NormalCallbackSet(
            read_callback=sim.read,
            write_callback=sim.write,
            read_block_callback=sim.read_block,
            write_block_callback=sim.write_block,
        )
    )


@pytest.fixture
def regs():
    return make_sim_regs()


def test_reset_values(regs):
    assert regs.START_REG.START.read() == 0
    assert regs.MEM_MODE_REG.MEM_MODE.read() == 0


def test_control_bits_roundtrip(regs):
    regs.MEM_MODE_REG.MEM_MODE.write(1)
    assert regs.MEM_MODE_REG.MEM_MODE.read() == 1


def test_addr_len_roundtrip(regs):
    regs.MEM_ADDR_REG.MEM_ADDR.write(0x1234_5678)
    regs.MEM_LEN_REG.MEM_LEN.write(100)
    assert regs.MEM_ADDR_REG.MEM_ADDR.read() == 0x1234_5678
    assert regs.MEM_LEN_REG.MEM_LEN.read() == 100


def test_load_dmem_sequence(regs):
    # Mirrors driver.load_dmem(): MODE=1, ADDR, LEN, START=1, <DMA>, START=0
    regs.MEM_MODE_REG.MEM_MODE.write(1)
    regs.MEM_ADDR_REG.MEM_ADDR.write(0)
    regs.MEM_LEN_REG.MEM_LEN.write(100)
    regs.MEM_START_REG.MEM_START.write(1)
    assert regs.MEM_START_REG.MEM_START.read() == 1
    regs.MEM_START_REG.MEM_START.write(0)
    assert regs.MEM_START_REG.MEM_START.read() == 0
```

Run:

```bash
cd cores/ip/<ip_name>/driver/tests
pytest test_<ip_name>_regs.py -v
# or from the repo root:
pytest cores/ip/<ip_name>/driver/tests/ -v
```

## Writing the QICK Driver

There are two valid driver styles.

### Style A — Manual driver (hardcoded register offsets)

Used by the tProcV1 driver. The driver does NOT import the generated package; it
accesses registers by index and implements memory access by AXI address (upper
window). The generated package is then only for docs / register-layer tests.

```python
class AxisTProc64x32_x8(SocIP):
    bindto = ['user.org:user:axis_tproc64x32_x8:1.0',
              'QICK:QICK:axis_tproc64x32_x8:1.0']
    NREG = 64  # words reserved for registers (256 bytes); DMEM window starts above

    REGISTERS = {'start_src_reg': 0, 'start_reg': 1,
                 'mem_mode_reg': 2, 'mem_start_reg': 3,
                 'mem_addr_reg': 4, 'mem_len_reg': 5}

    def single_read(self, addr):
        # data memory single access via the upper AXI window
        return self.mmio.array[addr + self.NREG]

    def single_write(self, addr=0, data=0):
        self.mmio.array[addr + self.NREG] = np.uint32(data)
```

> The custom AXI slave (`axi_slv_tprocv1`) is REQUIRED for this style: it decodes
> low addresses as registers and high addresses (>= NREG*4) as single DMEM
> accesses with an exec/exec_ack handshake, returning SLVERR while the memory
> arbiter is busy. A generated `peakrdl regblock` cannot do this.

### Style B — Generated-package driver

Used by simple register-only IPs (`axis_constant_iq`). The driver imports the
generated model and accesses fields by name.

```python
import sys
from pathlib import Path
from typing import Tuple
import numpy as np

_RDL_PKG_PATHS = [
    Path(__file__).parent.parent / "rdl",
    Path(__file__).parent.parent / "rdl_pkgs",
]
for _path in _RDL_PKG_PATHS:
    if (_path / "axis_constant_iq_regmap_pkg").exists():
        if str(_path) not in sys.path:
            sys.path.insert(0, str(_path))
        break

from axis_constant_iq_regmap_pkg.reg_model import RegModel
from axis_constant_iq_regmap_pkg.lib import NormalCallbackSet
from qick.ip import SocIP


def _to_unsigned(val, bits=16):
    return val & ((1 << bits) - 1)

def _to_signed(val, bits=16):
    half = 1 << (bits - 1)
    return val - (1 << bits) if val >= half else val


class AxisConstantIQ(SocIP):
    bindto = ['user.org:user:axis_constant_iq:1.0']
    MAXV = 2**15 - 2
    IQ_BITS = 16

    def configure_connections(self, soc):
        super().configure_connections(soc)
        self._reg_model = RegModel(
            callbacks=NormalCallbackSet(
                read_callback=self._hw_read,
                write_callback=self._hw_write,
                read_block_callback=self._hw_read_block,
                write_block_callback=self._hw_write_block,
            )
        )

    def _hw_read(self, addr, width, accesswidth):
        return self.mmio.read(addr // 4)

    def _hw_write(self, addr, width, accesswidth, data):
        self.mmio.write(addr // 4, data)

    # read_block / write_block callbacks as needed by your QICK version

    @property
    def regs(self):
        return self._reg_model

    def set_iq(self, i=1.0, q=1.0):
        i_int = int(np.clip(i, -1, 1) * self.MAXV)
        q_int = int(np.clip(q, -1, 1) * self.MAXV)
        self.regs.REAL_REG.I.write(_to_unsigned(i_int, self.IQ_BITS))
        self.regs.IMAG_REG.Q.write(_to_unsigned(q_int, self.IQ_BITS))
        self.regs.WE_REG.WE.write(1)

    def get_iq(self) -> Tuple[float, float]:
        i_raw = _to_signed(self.regs.REAL_REG.I.read(), self.IQ_BITS)
        q_raw = _to_signed(self.regs.IMAG_REG.Q.read(), self.IQ_BITS)
        return (i_raw / self.MAXV, q_raw / self.MAXV)
```

## Using the Driver on Hardware (QickSoc)

The driver is loaded automatically by QICK when the IP's **VLNV**
(vendor:library:name:version) matches one of the strings in the driver's
`bindto`.

```python
import numpy as np
from qick import QickSoc

soc = QickSoc('axis_tprocv1.bit')

# Find your block (name comes from the block design)
print(soc.ip_dict.keys())
tproc = soc.axis_tprocv1_0          # adjust to the real instance name

# Single access to data memory (upper AXI window -> axi_slv_tprocv1)
tproc.single_write(addr=10, data=0xDEADBEEF)
print(hex(tproc.single_read(addr=10)))

# Data memory via DMA
buff = np.arange(100, dtype=np.int32)
tproc.load_dmem(buff, addr=0)
out = tproc.read_dmem(addr=0, length=100)
assert np.array_equal(buff, out)

# Run a program
tproc.load_bin_program(binprog, load_mem=True)
tproc.start_src("internal")
tproc.start()
```

> VLNV / bindto MUST MATCH
>
> If you rename the IP module (e.g. `axis_tproc64x32_x8` -> `axis_tprocv1`), the
> package VLNV and the driver `bindto` can drift apart and QICK will NOT load the
> driver. Either:
>   - keep the IP name (`make package IP=... --ip-name axis_tproc64x32_x8`) so
>     the existing `bindto` matches, OR
>   - update `bindto` to the new VLNV (e.g. `qick:ip:axis_tprocv1:1.0`).
> The RTL module name and the IP/VLNV name may differ; what matters for driver
> loading is the VLNV vs `bindto`.

Smoke test on the board (mirrors the RTL tests tc02/tc05/tc07):

```python
for a in range(8):
    tproc.single_write(a, 0x1000_0000 + a)
for a in range(8):
    assert tproc.single_read(a) == 0x1000_0000 + a
print("single R/W OK")

buff = (np.arange(64) + 0xAA00).astype(np.int32)
tproc.load_dmem(buff, addr=0)
assert np.array_equal(buff, tproc.read_dmem(0, 64))
print("DMA R/W OK")
```

## Makefile Targets

| Command | Description |
|---------|-------------|
| `make driver IP=<name>`  | Generate RDL Python package + QICK driver symlink |
| `make gen IP=<name>`     | Generate RDL only (no symlink) |
| `make rdl-docs IP=<name>`| Generate HTML documentation from RDL |
| `make sim IP=<name>`     | Run the SVUnit RTL testbench |
| `make new-ip IP=<name>`  | Create a new IP from template |
| `make driver-all`        | Generate drivers for all IPs |

## Signed vs Unsigned Fields

PeakRDL-python validates fields as unsigned. For signed values (e.g. 16-bit IQ),
convert with helpers:

```python
def _to_unsigned(val, bits=16):
    return val & ((1 << bits) - 1)

def _to_signed(val, bits=16):
    half = 1 << (bits - 1)
    return val - (1 << bits) if val >= half else val
```

Writing a negative value directly raises
`ValueError: value ... must be greater than or equal to 0`. Wrap with
`_to_unsigned()`.

## Troubleshooting

**`make driver` runs `... _regmap.rdl` (empty name)**
The `rdl/Makefile` has a duplicated/empty `RDL_FILE`. Fix the Makefile heredoc
in `create_ip.sh` to use `<< 'EOF'` (no backslashes) and remove the duplicate
line.

**`make driver` runs `... ip_regmap.rdl`**
`IP_NAME` uses two `dirname` calls and resolves to `ip`. Use a single `dirname`:
`IP_NAME = $(shell basename $(shell dirname $(CURDIR)))`.

**`make ... gen: missing separator`**
Recipe lines use spaces instead of TABs. Use the `@@TAB@@` + `sed` trick.

**`ModuleNotFoundError: No module named '<ip>_regmap_pkg'`**
The package was not generated. Run `make driver IP=<name>` and ensure
`conftest.py` adds `rdl/` to `sys.path`.

**`TypeError: callbacks ... NormalCallbackSet`**
You passed too few callbacks. Provide all four:
`read_callback`, `write_callback`, `read_block_callback`, `write_block_callback`.

**Import of the model class fails (hash-suffixed name)**
Do not import `<ip>_neg_0x..._cls` directly. Import the clean alias
`RegModel` from `<ip>_regmap_pkg.reg_model`.

**Generated regblock SystemVerilog conflicts with the custom AXI slave**
You left `--hdl` in `gen` for a strategy-2 IP. Remove `--hdl`; keep only
`--python` (and `--html` for docs).

**Driver works in dev but not on the board**

`bindto`. Re-run `make driver`, redeploy, and verify the IP VLNV equals one of
the `bindto` strings.

## Lessons Learned (summary)

- Use a **faithful BRAM model** (synchronous, registered, write-first like
  `bram_tdp`) in RTL testbenches — idealized combinational models hide real
  read-latency bugs.
- AXIS writers must advance address/pipeline only on **accepted beats**
  (`tvalid && tready`), not on `tvalid` alone — otherwise the first beat is lost
  when `tvalid` leads `tready` at transaction start.
- In testbenches, do not sample combinational outputs of **single-cycle states**
  right after `wait_state`; use a concurrent `fork` monitor or settle a cycle.
- Synchronize multi-transaction tests on **real state** (`tready`/`busy`), not on
  fixed `repeat` margins.
- For PeakRDL: import the **clean aliases** (`RegModel`, `Simulator`), provide
  **four callbacks**, and treat the generated `_*_sim_test_base.py` as the
  source of truth for the API.
- Keep `axi_slv_tprocv1` for IPs that need a memory window + handshake; the RDL is
  for the **driver layer and docs only** in that case (no `--hdl`).
